# SALKN — подготовка размещения на REG.RU

Состояние: 16.09.2026. Ни публикация, ни изменение DNS, ни отправка в Telegram пока не выполнялись.

## Известные параметры

- Основной адрес по умолчанию: https://salkn.ru/.
- Второй домен: salkn.online; планируется постоянное перенаправление на основной адрес с сохранением пути.
- Услуга: виртуальный хостинг Host-0, панель ispmanager; это не VPS.
- Сервер хостинга: server159.hosting.reg.ru, IP 31.31.196.161.
- Имя аккаунта на скриншоте: u3649492; сверить с разделом «Доступы».
- На скриншоте REG.RU требуется идентификация владельца услуги. Её проходит владелец в личном кабинете.
- Оба домена уже перечислены в карточке услуги. Существующие папки и настройки нужно прочитать до изменений.

## Передача доступов

В корне проекта создан `.env.local` с правами 0600. Он исключён через `.gitignore`, находится вне `dist/` и не раздаётся локальным сервером. Заполнить `TELEGRAM_BOT_TOKEN`; `TELEGRAM_CHAT_ID` можно определить позже. Для размещения заполнить данные SSH/SFTP услуги хостинга. Пароль общего аккаунта REG.RU не нужен.

Не выводить содержимое этого файла в логи, переписку или аргументы команд. Не выполнять его через shell `source`. При будущей загрузке брать только явно указанные публичные файлы, а серверные секреты размещать за пределами корневой папки сайта. `.env.example` содержит только пустые секреты и открытые параметры.

Для привязки личного чата владелец открывает своего бота и нажимает «Запустить» / отправляет `/start`. Для группы — добавляет бота в нужную группу и отправляет команду `/start@имя_бота`. Если бот уже используется другим приложением, не сбрасывать webhook и не поглощать чужие обновления без отдельного разбора.

Владелец запросил двух получателей в разных личных чатах. Каждый из них должен запустить бота со своего Telegram-аккаунта. При подключении определить оба chat ID и задать явный список разрешённых получателей на сервере. Само нажатие `/start` посторонним пользователем не должно выдавать доступ к заявкам. Доставку и повторы учитывать отдельно для каждого получателя.

## План реализации

1. Проверить SSH/SFTP, корневые папки доменов, доступные версии PHP, cURL, PDO MySQL, cron, сертификаты и текущую зону DNS. Не переустанавливать сервер и не менять тариф без необходимости. Не отключать проверку сертификатов/SSH host key.
2. Реализовать обработчик формы на PHP и базу MySQL с проверкой телефона, услуги, бренда, согласия, длины полей и ограничением частоты. Сначала сохранять заявку и версию согласия в российской базе, затем ставить сообщение в очередь. Режим предпросмотра остаётся до готовности обработчика.
3. Передавать полные заявки боту только из серверного кода. Сообщение: номер обращения, время, имя, телефон, услуга, бренд и комментарий. Отключить интерпретацию пользовательского текста как разметки и предпросмотр ссылок. Ошибка Telegram не должна терять заявку: очередь и повторы через cron. Не логировать токены и содержимое заявок.
4. Подтвердить фактического оператора, продавца и исполнителя; местонахождение базы и копий; получателей/страны передачи Telegram. Обновить документы и выполнить необходимые уведомления РКН. Сам выбор полного сообщения владельцем не заменяет основание обработки данных посетителей.
5. Подготовить HTTPS на обоих доменах и www, затем перенаправление дополнительных адресов на https://salkn.ru/. Проверить все варианты адреса. Canonical, sitemap и URL в разметке уже подготовлены локально.
6. Развернуть после проверки доступа и конфигурации. Пройти тестовую заявку с вымышленными данными, проверить согласие, сохранение и доставку. Только затем включить рабочую форму и индексацию основной страницы. Юридические страницы можно оставить noindex.

## Что ещё нужно от владельца

- Токен бота в `.env.local` и сообщение боту для определения чата.
- Доступ SSH/SFTP либо доступная авторизованная панель; фактические корневые папки прочитать после подключения.
- Пройти требуемую REG.RU идентификацию.
- Уточнить продавца оборудования, исполнителя монтажа, получателя оплаты и того, кто имеет доступ к заявкам.
- Подтвердить размещение данных и копий в РФ по договору/сведениям хостера, подготовить уведомления РКН и условия передачи Telegram.
